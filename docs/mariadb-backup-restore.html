1 What is (and isn't) in the database

Understanding the scope of a database backup avoids surprises during a restore.

Stored in the database ✓NOT stored — lives on disk ✗
Libraries and their paths Actual book files (./books/)
All book metadata & read progress Cover images & thumbnails (./data/)
Shelves and shelf assignments AI model files (./data/ai-models/)
User accounts and preferences Author images (./data/author-images/)
App settings (all admin config) Bookdrop temp files (./bookdrop/)
Custom media types and categories
⚠
Important A full Booklore backup requires both a database dump and a copy of your book files and ./data/ directory. The database backup alone will not recover your books.

2 Prerequisites

  • Docker is installed and the Booklore stack is deployed
  • Your shell is in the same directory as your docker-compose.yml
  • The .env file is present with MYSQL_ROOT_PASSWORD, DB_USER, and DB_PASSWORD set
  • Sufficient disk space for the dump file (check with df -h .)

All commands below use the root account for maximum reliability. Load your credentials into the current shell session first:

# Load your .env variables into the current shell
export $(grep -v '^#' .env | xargs)
ℹ
Note The mariadb-dump command (not mysqldump) is used here because the linuxserver.io MariaDB image ships mariadb-dump as the canonical tool name. On older images the alias mysqldump also works, but mariadb-dump is preferred.

3 Logical backup — recommended

A logical backup exports the database as a SQL text file using mariadb-dump. It is portable, human-readable, and works with any compatible MariaDB version. The Booklore database is typically small (a few MB), so this is fast and easy to manage.

Basic dump

docker exec mariadb mariadb-dump \
  --single-transaction \
  --quick \
  --no-tablespaces \
  -u root -p"$MYSQL_ROOT_PASSWORD" \
  booklore > booklore_backup.sql
--single-transaction
Takes a consistent snapshot without locking tables (safe for InnoDB while the app is running).
--quick
Streams rows directly to output instead of buffering them in memory — important for large tables.
--no-tablespaces
Omits tablespace metadata that the Booklore DB user cannot re-import anyway.

Timestamped backup (recommended for routines)

docker exec mariadb mariadb-dump \
  --single-transaction --quick --no-tablespaces \
  -u root -p"$MYSQL_ROOT_PASSWORD" \
  booklore > "booklore_backup_$(date +%Y%m%d_%H%M%S).sql"

Compressed backup (saves disk space)

docker exec mariadb mariadb-dump \
  --single-transaction --quick --no-tablespaces \
  -u root -p"$MYSQL_ROOT_PASSWORD" \
  booklore | gzip > "booklore_backup_$(date +%Y%m%d_%H%M%S).sql.gz"
✓
Best practice Store backup files outside your compose directory — e.g. ~/booklore-backups/ — so they are not accidentally overwritten by an update or git pull, and are easy to find during a disaster recovery.

4 Physical / volume backup

A physical backup copies the raw database files on disk. It is faster than a logical dump for very large databases, but must be done while MariaDB is stopped to avoid corruption.

  1. Stop the entire Booklore stack 
    docker compose down
  2. Copy the MariaDB config/data directory 
    cp -r ./mariadb/config "./mariadb_config_backup_$(date +%Y%m%d_%H%M%S)"

    The linuxserver image stores all database files under ./mariadb/config/. This command copies the entire directory.

  3. Restart the stack 
    docker compose up -d
⚠
Warning Copying volume files while MariaDB is running will produce an inconsistent backup that may not restore correctly. Always stop containers first.

5 Restoring a backup

Restore from a logical dump (.sql)

  1. Stop the Booklore application container (keep MariaDB running) 
    docker compose stop booklore
  2. Import the backup into the existing booklore schema 
    docker exec -i mariadb mariadb \
  -u root -p"$MYSQL_ROOT_PASSWORD" \
  booklore < booklore_backup.sql

    Replace booklore_backup.sql with the path to your actual dump file.

  3. Restore from a compressed backup (if you used gzip) 
    gunzip -c booklore_backup.sql.gz | docker exec -i mariadb mariadb \
  -u root -p"$MYSQL_ROOT_PASSWORD" \
  booklore
  4. Restart the Booklore app 
    docker compose start booklore
✖
Critical The Booklore DB user has GRANT ALL ON booklore.* — it cannot create a new database. You must always restore into the existing booklore schema (as shown above), not try to drop and recreate it with the app user.

Restore from a physical backup

  1. Stop the whole stack 
    docker compose down
  2. Replace the data directory with your backup copy 
    # Replace with the name of your backup directory
rm -rf ./mariadb/config
cp -r ./mariadb_config_backup_YYYYMMDD_HHMMSS ./mariadb/config
  3. Restart the stack 
    docker compose up -d

Restoring to a fresh install

If you're moving to a new machine or starting from scratch:

  1. Deploy Booklore normally and let it initialize the database (docker compose up -d). Wait for the booklore container to become healthy.
  2. Stop the app container: 
    docker compose stop booklore
  3. Import your backup: 
    docker exec -i mariadb mariadb \
  -u root -p"$MYSQL_ROOT_PASSWORD" \
  booklore < booklore_backup.sql
  4. Restart the app: 
    docker compose start booklore
  5. Log in as admin and verify library paths. If paths changed between systems, update them in Settings → Libraries and trigger a rescan.

6 Automating backups with cron

Run crontab -e and add an entry. The example below creates a nightly compressed backup at 2 AM and prunes files older than 30 days.

# Booklore — nightly MariaDB backup (runs at 02:00 every day)
0 2 * * *  \
  BACKUP_DIR=$HOME/booklore-backups && \
  COMPOSE_DIR=/path/to/your/compose/directory && \
  mkdir -p "$BACKUP_DIR" && \
  source "$COMPOSE_DIR/.env" && \
  docker exec mariadb mariadb-dump \
    --single-transaction --quick --no-tablespaces \
    -u root -p"$MYSQL_ROOT_PASSWORD" \
    booklore | gzip > "$BACKUP_DIR/booklore_$(date +\%Y\%m\%d_\%H\%M\%S).sql.gz" && \
  find "$BACKUP_DIR" -name 'booklore_*.sql.gz' -mtime +30 -delete
✓
Tip Replace /path/to/your/compose/directory with the absolute path to the directory containing your docker-compose.yml and .env files. Adjust the retention window (-mtime +30) as needed.

Optional: copy backups off-site

Append a rclone or rsync call to push backups to a remote location after the dump:

# After the dump command, sync to a remote (requires rclone configured)
rclone copy "$BACKUP_DIR" remote:booklore-backups

7 Verifying a backup

Check the file is non-empty and valid SQL

# Should report a size and that the file ends with '-- Dump completed'
ls -lh booklore_backup.sql
tail -3 booklore_backup.sql

Quick row-count sanity check after restore

docker exec -it mariadb mariadb \
  -u root -p"$MYSQL_ROOT_PASSWORD" \
  -e "SELECT table_name, table_rows
      FROM information_schema.tables
      WHERE table_schema = 'booklore'
      ORDER BY table_rows DESC;" booklore

Verify the compressed dump is intact

gunzip -t booklore_backup.sql.gz && echo "Archive OK"
✓
Best practice Periodically do a full test restore to a separate MariaDB container to confirm your backups are actually usable. A backup you have never tested is a backup you cannot trust.

8 Important caveats

⚠
Library paths Library paths are stored in the database. If you restore to a machine where the book directory is at a different path (e.g. /mnt/nas/books instead of /books), libraries will appear offline. Fix them in Settings → Libraries and trigger a rescan.
⚠
Media files are separate Your actual book files (./books/), cover images, and thumbnails (./data/) are not in the database. Back them up separately — the database backup alone is not sufficient for a complete recovery.
⚠
Port 3306 exposure The default docker-compose.yml exposes port 3306 to all interfaces. For production use, consider binding it to 127.0.0.1:3306:3306 or removing the port mapping entirely if you don't need external DB access.
ℹ
Settings export vs. full DB backup The Booklore admin panel includes a Settings export option — this only exports application settings, not the full database. Use the commands in this guide for a complete backup that includes libraries, books, users, shelves, and all metadata.
