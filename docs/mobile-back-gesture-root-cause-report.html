Mobile Back Gesture: Root Cause and Evidence-Based Fix

Date: 2026-04-18 | Scope: Mobile back/edge-swipe behavior across BookLore UI surfaces

Root Cause Confirmed Fix Implemented Regression Coverage Added Release Tagging Follows Validation

User Symptom

  • On Android, edge-swipe/back frequently navigated away while mobile UI overlays were still open.
  • Users expected back to close the currently open popup/panel first, then navigate only after overlays were dismissed.
  • Behavior was inconsistent by feature area and reader type.

Root Cause

  • Back handling was fragmented into one-off implementations instead of one shared stack.
  • Only a small subset of mobile surfaces integrated history/popstate logic.
  • Most overlays had local open/close state but no back-stack registration, so route navigation won the race.

Reverse Engineering Findings

AreaStatus Before FixGap
Book browser mobile filter sidebarHad bespoke popstate/history logicNot reusable, duplicated lifecycle complexity
Metadata image previewHad local popstate close listenerIsolated implementation
Book card mobile preview / physical viewerNo shared back registrationBack could navigate away with viewer still open
EPUB/CBX readers and topbar popoversMultiple open surfaces, no unified back-stack behaviorInconsistent close order and user experience
Audiobook mobile side panelsLocal toggles onlyNo system-back-first close guarantee

Fix Architecture

  • Introduced a centralized service: mobile-back-navigation.service.ts.
  • Each mobile surface now registers a close handler when opened and releases it when closed/destroyed.
  • The first back event pops the most recent registered surface and closes it.
  • Route navigation proceeds only after the mobile UI stack is exhausted.
  • Legacy one-off logic in book browser was replaced with the shared path.
Core pattern (simplified) openSurface() { this.mobileBackHandle = this.mobileBackNavigation.register(() => this.closeSurfaceFromBack()); } closeSurface() { this.mobileBackHandle?.release(); this.mobileBackHandle = null; }

Integrated Surface Coverage

  • Book browser mobile right sidebar
  • Book card inline mobile preview
  • Physical books mobile viewer
  • EPUB reader sidebars/settings/dialog overlays
  • CBX reader sidebars/settings/dialog overlays
  • Topbar mobile popovers and menus
  • Audiobook mobile track/bookmark panels

Regression Coverage and Validation

  • PASS Focused regressions for popstate-driven close in shared book card and physical books viewer.
  • PASS Full frontend tests: 34 files, 584 tests.
  • PASS Frontend production build (Angular build).
  • PASS Backend test run (Gradle): BUILD SUCCESSFUL.

Test Environment Lesson Captured

  • Mobile-gated back-stack behavior depends on real window dimensions, not only component screen fields.
  • Regression specs now set and restore window.innerWidth/window.innerHeight to execute true mobile paths.

Outcome

Mobile back behavior is now deterministic and app-wide: if a popup, panel, or overlay is open, back closes that UI surface first. Navigation occurs only after stacked mobile surfaces are dismissed.
