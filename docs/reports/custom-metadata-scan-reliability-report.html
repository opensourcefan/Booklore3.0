Executive Summary

The custom metadata pipeline is resilient in several ways (task reconciliation and resume support), but one high-impact reliability gap remains: per-book failures can be emitted during processing yet the overall batch can still be marked completed at the end.

Reliability Recommendations

  • Track a hadErrors aggregate during batch loops and finalize as ERROR/COMPLETED_WITH_ERRORS rather than unconditional COMPLETED.
  • Return an explicit non-error task/event for zero-target scans to keep user feedback visible without polluting error channels.
  • Align frontend and backend REFRESH_METADATA_MANUAL async metadata to prevent queue-vs-sync messaging drift.
  • Optionally show a follow-up toast when task status transitions to completed/error for users who launch from custom fetch dialogs.
