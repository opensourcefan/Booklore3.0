UX and Counting Notes

  • Messaging In remove-from-library flow, progress text in browser uses the pre-request selected count (book-browser.component.ts:933) while backend may trim affected IDs by permissions (BookService.java:439, :450).
  • Final authoritative deleted/removed IDs come from API response and are used for state removal (book.service.ts:189).
  • Expected Scan endpoint semantics are queue-and-return; completion should be read from task/log/progress channels, not the immediate 204 response.

Recommendation

If the product goal is "remove now, allow reimport on next scan," change new-file detection to optionally ignore removedFromLibrary records for scan-new-files mode (or provide a dedicated "Reimport removed books" option).
