1. What Is Fable?

Fable is a self-hosted digital library for organizing, reviewing, reading, and sharing access to books, comics, audiobooks, and physical-book records. The application and catalog run on your computer or server, while its browser interface lets permitted users work from other devices. Your files remain in storage locations you control rather than being moved to a third-party library service.

Supported Formats

You can add books by uploading directly to a library, sending files through BookDrop for pre-import review, or placing files in a configured host folder and scanning its library. You can also catalog physical books without digital files. See Section 6: Books for the complete import and staging lifecycle and Section 7: BookDrop for the BookDrop workflow.

EPUBCommon e-book format used by most e-readers
MOBI / AZW3Amazon Kindle e-book formats (MOBI, AZW, AZW3)

CBZ / CBR / CB7Comic book archives (ZIP, RAR, or 7-Zip image collections)
AudiobooksAudio files organized in folders (MP3, M4A, M4B, OGG, or OPUS)
PhysicalPrinted books or items in your real-world collection. Creating a physical book entry creates a catalog placeholder (no digital file required) so you can track your entire shelf in one interface.

Start with the Task You Want to Complete

  • Finish setup and add your first book: follow Section 2, then choose an import route in Section 6.
  • Separate collections by storage location or access: learn library boundaries and library tools in Section 5.
  • Review every new catalog entry before normal use: use the Staging lifecycle in Section 6.
  • Prepare filenames and metadata before import: use Section 7: BookDrop.
  • Organize books: use shelves and Magic Shelves in Section 8 and Section 9, or browse series and authors in Section 13.
  • Read or listen in a browser: open Section 10; bookmarks and notes are covered in Section 11.
  • Find books: use metadata search, filtering, or AI Search as described in Section 17.
  • Connect readers and other users: see OPDS, Kobo and KOReader sync, email, and accounts and profiles.

2. Getting Started — First-Time Setup

To access the Setup Wizard, open a web browser and navigate to your server's address and port—by default, http://<your-server-ip>:6060, or http://localhost:6060 from the host itself.

What You Do

  1. Create your admin account — Choose a username and strong password. This is the main administrator account. The email field is optional for local accounts — it is only used for OIDC (Single Sign-On providers like Authentik, Keycloak, or Pocket ID) identity matching (see Section 22). You can leave it blank if you are not using OIDC.
  2. Set up your first library — Point Fable to the folder where your books are stored. Enter the path inside the Docker container (typically /books), which maps to the physical folder on your host machine.
  3. Configure authentication — Choose how users will log in (local password, OIDC, or forward auth).

What You Can’t Do

  • You cannot skip creating the admin account — it is required.
  • You can change your username later from your user profile. Fable may also ask an invited user to confirm or change it during the first-login credential update.
  • You cannot undo the first-time setup once completed — but you can change all settings afterward.
Be Careful: Choose a strong password. Anyone who knows this password has full control over Fable. There is no anonymous “Forgot Password” email reset by default. Another admin can issue a temporary password; if the sole admin loses every working local/OIDC login, stop and follow the supported recovery boundary in Section 22 rather than editing password hashes or improvising database commands.

After the Wizard: Add and Check Your First Book

  1. Choose an import route. Use topbar Upload to send a browser file straight to a selected library path, use BookDrop when you want a review-and-finalize inbox, or copy a file into the library’s host folder and run Scan for New Files. The differences are explained in Section 6.
  2. Open HOME → Staging. Every newly created digital or physical catalog entry starts with staged=true. Confirm its title, author, cover, media type, and destination.
  3. Fetch or edit metadata if needed. A metadata fetch may finish automatically, produce a proposal in Review, or require a manual action. See the Staging lifecycle.
  4. Open the book. Verify that a digital file reads or plays correctly. Physical entries have no readable file by design.
  5. Release it from Staging. Select the book and choose Release. This only clears its staged status; it does not move the file or remove library, shelf, or metadata assignments.

Open Fable on a Second Device

On another computer, tablet, or phone that can reach the server, open http://<your-server-ip>:6060 and sign in. Use the server’s LAN hostname or IP address—localhost on the second device refers to that device, not the Fable server. Browser layout preferences can differ by device, while account-backed settings such as HOME shortcut visibility follow your account. If the page cannot connect, confirm that both devices can reach the same network and that port 6060 is exposed by the host.

Joining an existing Fable (not the first-time wizard)

If someone already runs Fable and invited you, you skip this Setup Wizard. Use the username and temporary password they sent you, sign in, change your password when asked, then open the User Guide from the sidebar. Details: Section 22 — If someone invited you to Fable.

3. The Dashboard — Your Home Screen

Sidebar HOME Dashboard

The Dashboard is the first screen you see after logging in. Use it to resume reading and to spot recent activity; use the task pages linked below when you need to import, review, organize, or maintain books.

  • Access recently added books, continue-reading shortcuts, and other quick-start content rows

  • Customize each row’s target library filter, width, and item count, and lock the layout to prevent accidental drag-and-drop reordering
  • Add books to the optional Currently Reading row from a book’s More Actions → Currently Reading menu item to access them with a single click
  • Enjoy a fully responsive layout that automatically adapts grid widths when viewed on desktop, tablet, or mobile screens
  • Jump to any section of the app using the sidebar navigation

  • Organize books: use Shelves, Magic Shelves, Series and Authors, or Story Arcs.
  • Search: use standard or AI-powered search as described in Section 17.

Notification Bell — Tasks & Notifications

Topbar Bell icon

The bell is Fable’s status center. Click it to open a popover with two tabs: Tasks and Notifications. They answer different questions: “What is running right now?” versus “What failed that I still need to know about?”

Tasks tab — live progress

The Tasks tab shows work in progress. When nothing is running, it shows No running tasks. When something is active, you may see:

  • Metadata jobs — bulk metadata downloads and review progress widgets
  • AI Search scans — batch embedding / indexing progress
  • System jobs — metadata flush to files, library file sync, directory tagging, metadata refresh, and related long-running work
  • BookDrop — a widget when files are waiting in the BookDrop folder

On phones, desktop-only status chips are hidden, so those same system jobs are surfaced inside this Tasks tab so you can still monitor them.

Notifications tab — durable failures

The Notifications tab is a failure inbox, not a general activity feed. Only WARN and ERROR items appear here. Successful / informational chatter does not fill this list.

  • Persistent — Failures are saved to the database for your account, so they survive page reloads and server restarts (recent history, up to about 50 items)
  • Each entry shows a severity tag, a timestamp, and the message
  • Dismiss one with the × on that row, or Dismiss All to clear the inbox
  • Empty state: No failures to show.
  • The Notifications tab shows a small count badge when unread failures exist

Configure whether scheduled failures appear in the inbox with the per-task Error notifications toggle under Settings → Tasks. When that toggle is on, scheduled failures go to the Notifications tab; successful runs are recorded under Recent runs only.

Tip: If something “didn’t work” but you missed the moment it failed, open the bell and check the Notifications tab first. Live progress belongs on Tasks; lasting problems belong on Notifications.

What You Can Do

  • Resize sidebars — Drag the edge of either sidebar to make it wider or narrower
  • Reorder sidebar items — Click Re-order next to the sidebar controls, then drag rows to customize the sidebar list; click Re-order again to save
  • Collapse sections — Click section headers to expand or collapse groups; Fable remembers each section’s open/closed state in this browser so it survives refresh
  • Synchronize layout settings across devices — Your sidebar heading visibility, HOME shortcuts, and media type order are saved directly to your account so they follow you on any browser or device you use
  • Read the User Guide in the built-in reader — The footer link opens this guide directly; if you want to highlight it or take notes, you can import the PDF into a library like any other book
  • Browse by folder — Click the folder button in the book toolbar to open the directory explorer
  • Toggle browser fullscreen mode — Click the fullscreen icon in the topbar to hide browser tabs and let Fable take up the entire screen
  • Clear failure history — Open the bell, switch to Notifications, and click Dismiss All
Good to Know: Switching between sidebar views does not reload your books from scratch—Fable remembers where you were, so navigation is instant. Failure notifications in the bell are saved securely, so they won’t disappear if your server restarts. The popover closes automatically when there is nothing left to show (no running tasks, no failures, and no active highlights).

5. Libraries — Organizing Your Collection

Sidebar LIBRARIES section

A Library is a storage boundary: it connects one catalog collection to one or more configured host or mounted directories. Its paths, permitted media formats, access rules, naming pattern, metadata behavior, and maintenance operations apply to the books inside that boundary. A shelf can group books across libraries, but it does not change where their files are stored.

What You Can’t Do

  • Treat one folder as two independent storage boundaries; each configured folder should belong to one library
  • Manage files on remote cloud services directly — Fable reads from local or network-mounted folders
Be Careful:
  • Deleting a library removes the catalog entry, not the source files on disk. If you want to delete real book files, that happens through book-file deletion flows, not library removal.
  • Moving or renaming book files outside of Fable will cause them to appear missing. Always let Fable manage file movements.
  • Use maintenance operations intentionally. They are broader than the additive Scan for New Files action.
  • If your book folder is on a network drive, set DISK_TYPE=NETWORK in your environment configuration (the .env file) for better compatibility. Automatic metadata writes stay disabled there, but you can still run manual sidecar backups when you want a portable metadata snapshot.

Staging Lifecycle: Staged, Review, Completed, Release

Sidebar HOME Staging

New digital imports and newly created physical-book records begin with staged=true. Staging is a triage flag, not a separate storage location: the book already belongs to its selected library. Use the tabs to decide what still needs attention.

Tab/actionMeaning and next step
StagedThe staged inbox: books that do not currently have a pending metadata proposal and are not classified as completed. Inspect the book, edit metadata, or start a metadata fetch. On desktop and tablet, an amber barcode badge means ISBN Discovery completed without finding a valid ISBN; a red warning badge means the ISBN check could not be completed. Hover either badge for the recorded reason and check time. Books without either badge have no recorded ISBN problem.
ReviewBooks with fetched metadata proposals awaiting a decision. Open the metadata review, compare proposed and current values, then apply or reject as appropriate. Pending review wins over the other triage buckets; a review item can remain visible even if its staging flag was previously cleared.
CompletedStaged books whose metadata fetch has completed or whose ISBN has been verified, with no pending review proposal. Check the result before release.
ReleaseSelect one or more books and click Release. This changes only staged from true to false. It does not move files, alter metadata, change library or shelf membership, or delete anything.
Suggested loop: import → open Staged → correct or fetch metadata → resolve Review items → check Completed → select the books → Release.

Directory Explorer

Book browser toolbar folder toggle button (left side of the header bar)

Fable includes a Directory Explorer — a collapsible folder-tree panel that slides out from the left side of the book browser. It lets you filter the current view by the actual folders on disk inside your libraries, exactly as they are organized in your filesystem.

Why Use the Directory Explorer?

If you already organize your collection into folders on disk — for example /Comics/Marvel/, /Books/Fiction/, or /Audiobooks/Sci-Fi/ — the Directory Explorer mirrors that structure directly in Fable. You can browse your library the same way you browse files on your computer, with zero metadata setup required. It is also a great complement to shelves and filters: use folders for broad organization and shelves for cross-cutting collections.

Opening and Closing

  • Open: Click the folder toggle button in the book browser toolbar (visible when viewing All Books or any library). The panel slides out from the left.
  • Close: Click the close icon in the panel header, or click the folder toggle again.
  • Resize: Drag the right edge of the panel to adjust its width. Your preferred width is remembered across sessions.
  • Collapse the left sidebar: If you need more horizontal room, collapse the main left sidebar first using the sidebar toggle button in the topbar to give both the folder tree and the book covers more space.

What is a metadata sidecar file?
A sidecar file is a small metadata file saved on disk beside a book or in the designated physical-book location. It can preserve details such as title, author, description, and ratings for later import or rebuilding. Physical-book creation writes a sidecar for the placeholder.
Physical Shelf View: The Physical Books page draws a custom shelf rail under each visual row, creating a virtual bookshelf display that wraps correctly as your collection grows.

What You Can’t Do

  • Directly edit the book file contents (Fable is a reader and organizer, not an editor)
  • Move or rename folders from the directory explorer (it is a filtering tool, not a file manager)
Be Careful:
  • Deleting a book with “delete from disk” enabled is permanent. The file is gone. There is no recycle bin.
  • Removing from Library vs. Deleting from Disk: Removing a record keeps its files. The removal submenu distinguishes removal until a future scan from permanent catalog suppression. Deleting from disk removes the real file.
  • Bulk deleting books is powerful — double-check your selection before confirming.
  • Deleting the last file: If you delete the only readable file from a digital book record, Fable removes the empty catalog card. To keep a catalog entry without a file, create a Physical Book entry instead.

7. BookDrop — Importing New Books

Topbar BookDrop

BookDrop is a watched, pre-import inbox. Files stay outside normal library browsing while you inspect metadata, choose a destination library and subpath, and finalize them. Finalization imports the book into its library; it does not bypass the Staging lifecycle.

Which inbox do I use? The global BookDrop is the shared/admin inbox inside the container (default /bookdrop, commonly mounted from a host folder such as ./bookdrop). Non-admin accounts use private inboxes under /books/_users/{id}/bookdrop/. Fable scopes pending-file access accordingly: admins work with global files, while non-admin users work with files owned by their account.

Put Files into BookDrop

Personal dropPlace files in the user’s /books/_users/{id}/bookdrop/ inbox, or use browser upload while signed in as that user. A .ignore marker keeps this inbox out of normal personal-library scans.

Use direct topbar Upload → Library instead when the library and subpath are already known and you do not need BookDrop’s pre-import review. The route comparison is in Section 6.

Review and Finalize

  1. Wait for detection or click Rescan, then open topbar BookDrop.
  2. Select pending files. Selection can cover the current page or all pages.
  3. Prepare metadata. Review fetched values, import selected metadata, bulk-edit fields, or extract metadata from filename patterns.
  4. Choose a destination. Assign a permitted library and subpath to every selected file; defaults can be applied to the selection.
  5. Finalize. Fable resolves the library naming pattern, moves each successful file into its destination, creates the library book record, applies the prepared metadata, and removes successful items from BookDrop. Failed items are reported in the import summary.
  6. Hand off to Staging. Open HOME → Staging, resolve any remaining metadata work, and release the new books when ready. See Section 6: Staging lifecycle.

A Story Arc is a curated reading order made up of chapters (rows) containing books (cards). Each chapter can represent a phase of the story, a collected edition, or a thematic grouping. AI Search

Topbar AI Search sparkle icon, or Settings AI Settings AI Search

If you have configured Fable with an AI model provider (or are using a built-in Fable Preset) and you have embedded books, you can leverage natural language search to find books based on themes, characters, concepts, or general queries.   • From Search Bars: Click the sparkly blue AI Search located inside the topbar or library search input fields to open the AI Search Dialog and submit your query.
  • From Book Cards: Look for the AIS badge on individual books in your library. Clicking this badge will open AI Search directly on that specific book, allowing you to ask questions about its contents, summarize it, or explore its themes.

What Is Embedding?

Think of embedding as Fable reading a book and creating a searchable "index card" for it. Just like a library card catalog lets you find books by topic without reading every page, Fable's AI reads your book's text, converts it into a mathematical representation (called a vector), and stores it in a database. When you ask a question like "find books with dragons," Fable compares your question against all those index cards to find the best matches — even if the word "dragon" never appears in the title or author fields. This is what makes AI Search so powerful: it understands meaning, not just keywords.

AIS Badge Color States — The AIS badge on book cards changes appearance to tell you the embedding status at a glance:

  • AIS Cyan on black — Book is fully embedded and ready for AI Search. Click the badge to ask questions about this book.
  • AIS Grey on grey — Book is marked for embedding but hasn't been processed yet. The AI service will pick it up on the next scan. Not clickable.
  • AIS Orange on black — Book was embedded with a different AI model than the one currently configured. The embeddings are stale and the book needs to be re-embedded. Click to see which model was used.

Save to Notepad: When you find a useful AI response, click Add to Notepad to save the snippet for later. See Bookmarks, Annotations, and the Notebook for the wider note-review workflow.

Sparkle Button Status Indicators — The sparkle in the search bars uses color and animation to reflect the AI Search service state:

  • Solid cyan — Service is ready. Click to open AI Search.
  • Flashing orange (800ms grey↔orange) — Service is warming up / downloading the embedding model. Wait for initialization.
  • Flashing red (800ms grey↔red) — Last search returned an error or no results. Click the sparkle to dismiss and retry.
  • Solid red — AI Search service is unreachable or encountered a fatal error. Check container logs.
  • Flashing cyan (800ms grey↔cyan) — A search is currently in progress. Results will appear in the dialog when ready.
Zero Configuration Needed:

Fable comes with everything you need built-in! The AI search engine runs automatically inside its own secure container. You don't need to install any external software or configure network settings to get started. Just pick a preset in your .env file and enjoy.

Configuration and tuning (LLM profiles, RAG techniques, embedding models, OCR, search parameters, and advanced retrieval settings) are covered in Section 24: Application Settings → AI Search & Embedding Tuning.

19. OPDS Feeds — E-Reader Integration

Settings OPDS tab

Choose a sharing route: use OPDS when an e-reader app should browse and download from Fable; use Devices for Kobo or KOReader progress sync (and optional Hardcover reporting); or use Email to send one selected file as an attachment. Opening Fable in a device’s web browser is ordinary browser access—it is not OPDS or device sync.

OPDS (Open Publication Distribution System) exposes a catalog endpoint to compatible reader apps. It is a pull workflow: the device browses Fable and downloads a book.

Set Up an OPDS Catalog

  1. Confirm your account has Access OPDS permission; otherwise ask an admin.
  2. Open Settings → OPDS and enable OPDS Server.
  3. Under Endpoints, copy the read-only OPDS Catalog URL.
  4. Under OPDS Users, click Add User, choose a username, password, and catalog sort order, then create the credential.
  5. In the e-reader app, add an OPDS catalog using the copied endpoint and that OPDS username/password. Do not use your normal Fable login unless you deliberately made the credentials identical.
  6. Browse the catalog and download a small book to verify the device can reach the Fable server.

What You Can Do

  • Browse your library from any OPDS-compatible e-reader or app
  • Download books directly to your e-reader
  • Use the catalog organization and search capabilities exposed to the OPDS client
  • Maintain separate OPDS credentials and choose each credential’s sort order

What You Can’t Do

  • Use OPDS to upload books to Fable; use the permission-gated BookDrop or Upload workflow instead
  • Assume an OPDS download synchronizes web-reader progress; configure Kobo or KOReader for supported progress sync
Be Careful: Treat the endpoint and OPDS credentials as secrets, use HTTPS outside a trusted LAN, and never expose Fable directly without a secured reverse proxy. Removing or changing an OPDS credential requires updating every client that uses it.

Settings Devices tab

The default method — log in with your username and password. Simplest option for personal and multi-user use. Passwords are stored securely (hashed). Sessions use JWT tokens that auto-refresh.

When an admin creates an invited user, they can Copy all an invite pack that includes a login link (often with ?reason=invite), username, and temporary password. Open that link, sign in, then change the password when prompted. See Section 22.

OIDC (OpenID Connect)

Use a third-party identity provider (like PocketID, Keycloak, or Authentik) for single sign-on.

  1. Log in as an admin and open Settings → OIDC.
  2. Copy the values in Provider Configuration Reference into a new client at the identity provider: redirect URI, post-logout redirect URI, back-channel logout URI where supported, required scopes, PKCE method, and grant type.
  3. In Fable, enter Provider Name, Client ID, optional Client Secret for a confidential client, Issuer URI, scopes, and username/email/name/groups claim mappings.
  4. Click Test Connection, expand the checks, and resolve failures before saving and enabling OIDC.
  5. Choose provisioning, local-account linking, group mappings, default libraries/permissions, session duration, and any mobile redirect URIs your deployment needs.
  6. Test a non-admin login and an admin login in a private browser window before enabling OIDC-Only Mode.

Forward Auth (Reverse Proxy)

Supported boundary: Fable currently has no Forward Auth toggle, trusted-header field, header-name mapping, or backend authentication mode exposed by this release. A reverse proxy may protect network access, but Fable still requires Local Login or OIDC. Do not inject identity headers and assume Fable will create or authenticate that user. Use the verified OIDC flow above when integrating Authentik, Authelia, Keycloak, Pocket ID, or another provider that offers OIDC.
Be Careful:
  • Never expose Fable directly to the internet. Use HTTPS and a properly secured reverse proxy.
  • OIDC requires exact URL and claim configuration. An incorrect issuer, redirect URI, client credential, scope, or username claim can prevent login or provisioning.
  • Local Login remains available to admins. In OIDC-Only Mode the supported admin entry point is /login?local=true; it still requires the valid local password.
  • Test before switching modes. Keep a working admin session open until both ordinary and admin OIDC logins have succeeded.

Search Tuning Parameters

Settings AI AI Search Engine Search Tuning

These sliders control how the AI Search retrieves and presents results. Each has a range slider with −/+ stepper buttons and a direct numeric input:

  • Top K (1–50, default 5): How many context chunks to retrieve from the vector database. More chunks give the LLM richer context but increase processing time.
  • Display Top K (1–50, default 1): How many raw results to show in the UI. Set this lower than Top K to give the LLM more context while showing only the best match to the user.
  • Similarity Threshold (0.10–0.90, default 0.30): Minimum relevance score for a chunk to be included. Lower values return more results (some may be less relevant); higher values are stricter.
  • Max Tokens (128–4096, default 768): Maximum length of the LLM’s generated summary. Higher values produce longer answers but take more time and memory.
  • Temperature (0.0–1.0, default 0.1): Controls randomness in the LLM output. 0.0 gives deterministic, focused answers. Higher values (0.5+) produce more creative and varied responses.

RAG Techniques

Settings AI AI Search Engine RAG Techniques

Retrieval-Augmented Generation (RAG) techniques enhance answer quality by adding processing steps between retrieval and response generation. Each technique has an independent toggle switch. Features that add LLM calls are automatically disabled when using a local LLM provider to avoid excessive latency on CPU-only hardware. They activate automatically when using an external (cloud) LLM.

  • HyDE (Hypothetical Document Embeddings): Generates a synthetic ideal answer to your query, then uses that to find similar content. Especially effective for abstract or conceptual queries. Adds 1 LLM call.
  • Multi-Query Retrieval: Expands your single query into multiple variant queries and fuses the results for broader coverage. Adds 1 LLM call + N retrievals.
  • Query Decomposition: Breaks complex questions into simpler sub-questions, answers each one, then synthesizes a complete response. Adds 1 LLM call + N retrievals.
  • Self-Reflection: After generating an initial answer, the LLM critiques its own response and regenerates if issues are found. Adds 1–2 LLM calls.
  • Contextual Compression: Filters retrieved chunks to only the most relevant sentences before they reach the LLM, keeping responses focused. No LLM calls — works with any provider.

Advanced Embedding & Retrieval Tuning

Settings AI AI Search Engine Advanced Embedding & Retrieval Tuning (click to expand)

This collapsible section (orange header, collapsed by default) contains low-level tuning parameters for the embedding and retrieval pipeline. It includes an Auto-Fill Recommended Presets button that loads optimal settings for your currently selected embedding model.

Be Careful: Modifying Chunk Size, Chunk Overlap, Semantic Chunking, or Matryoshka Dimensions changes how embeddings are structured. Saving changes to these settings will automatically delete all existing book embeddings and mark all books to be re-embedded. A confirmation dialog warns you before this happens. Search-only parameters (Hybrid Search or Reranking) do not invalidate existing embeddings.
  • Chunk Size (500–8000, default 1500): Maximum characters per text chunk during embedding. Larger chunks preserve more context but reduce search precision. Models with wide context windows (like Nomic at 8k) benefit from larger values.
  • Chunk Overlap (0–1000, default 100): How many characters overlap between consecutive chunks. Prevents key sentences from being cut at chunk boundaries.
  • Semantic Chunking: Toggle + threshold slider (0.10–0.50). When enabled, Fable splits books at natural text boundaries (paragraphs, sections) rather than at fixed character counts. The threshold controls how aggressively it detects boundaries — lower values create more chunks.
  • Matryoshka Dimensions: Dropdown (Disabled / 768 / 512 / 256 / 128). Supported by advanced models like Nomic, MRL allows slicing high-dimensional vectors down to fewer dimensions with almost no impact on retrieval accuracy. Slicing vectors and re-normalizing them speeds up cosine similarity comparisons on CPU by up to 3×, saving significant memory.
  • Hybrid Keyword Search (BM25 + Vector): Toggle + RRF K slider (10–200, default 60). Combines semantic vector similarity with traditional BM25 exact keyword matching using Reciprocal Rank Fusion. Highly effective at finding specific names, numbers, or technical codes that vector models might overlook.
  • Cross-Encoder Reranking: Toggle + model selector dropdown. Runs a lightweight cross-encoder model (such as BAAI/bge-reranker-base) in a background thread. While standard bi-encoders retrieve candidate chunks quickly, a cross-encoder evaluates the exact match relation between the query and text for the top candidates. This brings GPU-grade search precision to CPU hardware in milliseconds because it only reranks a handful of candidates instead of the whole database.

Routine Backup Procedure

  1. Prepare external storage. Use a destination separate from the Fable host and record the Fable/MariaDB version and deployment paths.
  2. Export app settings. Open Backups → App Settings, click Export, and store the downloaded JSON securely. It may contain sensitive configuration; it is not a database or media backup.
  3. Optionally write sidecars. Open Backups → Sidecar, select one library, click Back Up Sidecars per Library, and verify attempted equals exported with zero failed. Repeat for each required library.
  4. Prepare a logical database dump. As an admin, open Backups → Database Export, set the destination directory and filename, review the generated command for your deployment, and click Copy export command.
  5. Run the copied command outside Fable in the documented host/container environment. The UI only records that the command was copied; independently verify a non-empty SQL file was created.
  6. Copy companion data. Back up all library media, the mounted Fable app-data directory, and deployment configuration/path-mapping notes. Include BookDrop content if pending files matter to recovery.
  7. Validate the set. Confirm the SQL dump, app-settings JSON, media, app data, and deployment notes are readable from the recovery destination, then record checksums, sizes, date, and version.
Coverage boundary: App Settings JSON covers application configuration only. Sidecars preserve supported per-book metadata only. The logical SQL dump protects catalog/database state but not the media or app-data files. A recoverable set therefore needs the database dump plus matching media, app data, and deployment information.

Safe Restore Ordering

  1. Do not overwrite the only good copy. Preserve the incoming backup set and take a fresh backup of the current target before starting.
  2. Match the environment. Recreate or verify deployment configuration, mounts, service names, path mappings, and a compatible Fable/MariaDB version.
  3. Stage files first. Put library media and app data at the confirmed target paths with appropriate ownership and enough free space.
  4. Pause writes. Stop or isolate scans, uploads, BookDrop processing, metadata edits, scheduled tasks, and user traffic. The UI’s maintenance checkbox is an operator confirmation; it does not pause the system for you.
  5. Run the UI preflight. Open Backups → Database Restore; enter the SQL path, app-data path, deployment-config path, and measured free space. Confirm the SQL/notes, media, app data, config, version, and maintenance plan. The current check requires at least 15 GB entered free space.
  6. Resolve every failed check. Only after all checks pass should Copy restore command become available. The helper supports restoring into the existing fable schema; a temporary-schema restore is outside the current grants/UI boundary.
  7. Review and execute externally. Inspect the copied command against the actual service/container name and credential handling, then run it in the documented operator environment. Fable does not execute or verify that command.
  8. Start and validate. Bring services back in controlled order, wait for health checks/migrations, then validate login, user/library mappings, book counts, representative metadata, covers, reading progress, annotations, shelves, BookDrop, and one reader download before reopening writes.
  9. Retain rollback material. Keep the pre-restore target backup and original recovery set until validation and a subsequent fresh backup both succeed.
Be Careful:
  • Preflight is declarative. It checks entered values and confirmations; it does not inspect host files, versions, ownership, free space, or backup integrity.
  • Importing App Settings changes live configuration. Read the confirmation, keep a fresh export, and validate affected settings after import.
  • Database restore is destructive to current schema state. Use a maintenance window and a tested rollback; never paste an unreviewed command into production.
  • Secrets may be present. Protect settings JSON, SQL dumps, deployment files, OPDS/device credentials, SMTP credentials, and API keys.

28. Tips and Best Practices

For New Users

  1. If you were invited: follow the invited-user sign-in and profile procedure before exploring your personal library.
  2. Start small: follow the library setup procedure for one library, then add only a few test books with the BookDrop workflow.
  3. Use the supported import path: follow the permission-aware BookDrop versus Upload guidance instead of copying into another user’s area.
  4. Fetch metadata early: after import, follow the metadata fetch and review procedure to verify title, author, cover, description, and identifiers.
  5. Organize deliberately: follow the shelf creation and assignment procedure for hand-picked collections.
  6. Track reading: follow the reading-status and statistics procedure.

For Security

  1. Use unique strong passwords and follow the supported profile, admin-reset, and sole-admin recovery boundaries.
  2. Secure remote access by following the verified Local Login/OIDC setup and reverse-proxy boundary.
  3. Protect catalog credentials and follow the OPDS credential setup and rotation procedure.
  4. Grant only needed rights by following the role-preset and permission review procedure, especially for upload, BookDrop, library management, and deletion.
  5. Create and validate off-host recovery sets with the complete backup and restore procedure.

For Performance

  1. Choose and maintain comic formats using the supported-files and book-file procedure; prefer CBZ where your source workflow permits it.
  2. Test large scans with the CBX reader procedure before importing an entire high-resolution collection.
  3. Move expensive jobs to quiet periods with the Settings → Tasks scheduling procedure.
  4. Prefer additive discovery and use full reconcile only intentionally by following the scan-versus-reconcile guidance.

For Organization

  1. Normalize author records with the author browsing and editing procedure before treating similar names as separate people.
  2. Populate genres, categories, and identifiers with the metadata review procedure, then apply them through search and filters.
  3. Record ratings with the book details procedure, then use Magic Shelf rules to build rating-based collections.
  4. Build crossover orders with the Story Arc creation procedure instead of overloading ordinary shelves.
  5. Review highlights and notes with the Bookmarks and Notebook procedure.
