1. What Is Fable?

Fable is a self-hosted digital library — a personal application you run on your own computer or server to organize, read, and manage your book and comic collection. Because it is self-hosted, all your data, settings, and book files are stored locally on your own hardware rather than on a third-party cloud service, giving you complete ownership and privacy. You can access your private digital bookshelf from any web browser on any device in your network.

Supported Formats

To add books to Fable, you can upload them directly through the browser interface (using BookDrop) or place files into folders on your host server that are scanned by Fable. The following formats are supported:

FormatDescription
PDFStandard document files (books, manuals, magazines)
EPUBCommon e-book format used by most e-readers
MOBI / AZW3Amazon Kindle e-book formats (MOBI, AZW, AZW3)
FB2FictionBook 2 XML-based e-book format
CBZ / CBR / CB7Comic book archives (ZIP, RAR, or 7-Zip image collections)
AudiobooksAudio files organized in folders (MP3, M4A, M4B, OGG, or OPUS)
PhysicalPrinted books or items in your real-world collection. Creating a physical book entry creates a catalog placeholder (no digital file required) so you can track your entire shelf in one interface.

What You Can Do

  • Store and organize thousands of books across multiple libraries
  • Read books, comics, and listen to audiobooks directly in your browser
  • Track your reading progress across devices
  • Highlight text, add bookmarks, and write notes
  • Search and filter your entire collection
  • Fetch book information (metadata) from the internet automatically
  • Share your catalog with e-readers via OPDS feeds
  • Manage multiple users with different access levels
  • Use AI to detect comic panels for panel-by-panel reading
  • Use AI-powered natural language search to find books by theme, character, or concept
  • Create Story Arcs — guided reading paths with chapters for crossover events, shared universes, and curated reading orders

2. Getting Started — First-Time Setup

To access the **Setup Wizard**, open a web browser and navigate to your server's address and port—by default, this is http://<your-server-ip>:6060 (or http://localhost:6060 if running on your local machine).

What You Do

  1. Create your admin account — Choose a username and strong password. This is the main administrator account. The email field is optional for local accounts — it is only used for OIDC (Single Sign-On providers like Authentik, Keycloak, or Pocket ID) identity matching (see Section 22). You can leave it blank if you are not using OIDC.
  2. Set up your first library — Point Fable to the folder where your books are stored. Note: You must enter the path *inside the Docker container* (typically /books), which maps to the physical folder on your host machine's drive.
  3. Configure authentication — Choose how users will log in (local password, OIDC, or forward auth).

What You Can’t Do

  • You cannot skip creating the admin account — it is required.
  • You cannot change the admin username later through the normal interface.
  • You cannot undo the first-time setup once completed — but you can change all settings afterward.
Be Careful: Choose a strong password. Anyone who knows this password has full control over Fable. Because this is a private local app, there is no "Forgot Password" email reset by default. If you lose the admin password and have no other login method configured, recovery requires running database command-line queries inside the database container to manually reset the credential hash.

5. Libraries — Organizing Your Collection

Sidebar LIBRARIES section

A Library is a connection between Fable and a folder on your computer or server where book files are stored.

Scan vs. Reconcile — Which should you use?
  • Scan for New Files (Safe & Fast): Fable only looks for newly added book files and adds them to your library. It will not touch or overwrite your existing books or metadata. Use this for regular updates.
  • Reconcile Library (Deep Sync): Fable performs a full check of your library against your storage disk. It updates all library records to match the current disk contents, including removing catalog entries for files you deleted on disk. Reconcile requires an explicit confirmation before running.

What You Can Do

  • Create multiple libraries — For example, separate libraries for "Fiction," "Comics," or "Audiobooks"
  • Configure settings and folders — Manage names and display icons under Library Settings, and add or remove folder paths under Manage Directories
  • Choose directory scanning options — When editing directory paths, select Save to update folder list membership or Save & Scan New Directories to immediately import books from newly added folders
  • Access library maintenance tools — Perform advanced tasks like rebuilding libraries or exporting/importing metadata sidecar files from the Library Maintenance panel
  • Check library health — Verify Fable can reach the configured folders on disk
  • Restrict library access — Control which user accounts can view and search books in each library
  • Delete libraries — Remove a library from Fable's interface at any time (this removes the catalog but does **not** touch your files on disk)
Good to Know: Fable's library settings, directories, and maintenance dialogs are fully cross-linked, allowing you to easily click between configuration panels without exiting to the main menu. Scheduled scans are designed to be safe and use the additive "Scan for New Files" process to protect your existing metadata from unintended overrides.

What You Can’t Do

  • Assign the same folder to two different libraries (each folder should belong to one library)
  • Manage files on remote cloud services directly — Fable reads from local or network-mounted folders
Be Careful:
  • Deleting a library removes the catalog entry, not the source files on disk. If you want to delete real book files, that happens through book-file deletion flows, not library removal.
  • Moving or renaming book files outside of Fable will cause them to appear missing. Always let Fable manage file movements.
  • Use Reconcile Library intentionally. It is not the same as a safe new-file scan and may change existing library records to match disk.
  • If your book folder is on a network drive, set DISK_TYPE=NETWORK in your environment configuration (the .env file) for better compatibility. Automatic metadata writes stay disabled there, but you can still run manual sidecar backups when you want a portable metadata snapshot.

Directory Explorer

Book browser toolbar folder toggle button (left side of the header bar)

Fable includes a Directory Explorer — a collapsible folder-tree panel that slides out from the left side of the book browser. It lets you filter the current view by the actual folders on disk inside your libraries, exactly as they are organized in your filesystem.

Why Use the Directory Explorer?

If you already organize your collection into folders on disk — for example /Comics/Marvel/, /Books/Fiction/, or /Audiobooks/Sci-Fi/ — the Directory Explorer mirrors that structure directly in Fable. You can browse your library the same way you browse files on your computer, with zero metadata setup required. It is also a great complement to shelves and filters: use folders for broad organization and shelves for cross-cutting collections.

Opening and Closing

  • Open: Click the folder toggle button in the book browser toolbar (visible when viewing All Books or any library). The panel slides out from the left.
  • Close: Click the close icon in the panel header, or click the folder toggle again.
  • Resize: Drag the right edge of the panel to adjust its width. Your preferred width is remembered across sessions.
  • Collapse the left sidebar: If you need more horizontal room, collapse the main left sidebar first using the sidebar toggle button in the topbar to give both the folder tree and the book covers more space.

What is a metadata sidecar file?
A **sidecar file** is a small text file saved on disk in the same folder as your book. It stores metadata details like the title, author, description, and ratings. Having sidecar files acts as a local backup—if you ever move your books or need to rebuild Fable from scratch, Fable can quickly recreate your library setup directly from these files. Physical book placeholders also write sidecar files to their designated folder so they are not lost during database rebuilds.
Physical Shelf View: The Physical Books page draws a custom shelf rail under each visual row, creating a virtual bookshelf display that wraps correctly as your collection grows.

What You Can’t Do

  • Directly edit the book file contents (Fable is a reader and organizer, not an editor)
  • Upload books from this screen (use BookDrop for that — see Section 7)
  • Move or rename folders from the directory explorer (it is a filtering tool, not a file manager)
Be Careful:
  • Deleting a book with “delete from disk” enabled is permanent. The file is gone. There is no recycle bin.
  • Removing from Library vs. Deleting from Disk: If you turn off "Allow File Deletion" in settings, Fable will only let you remove books from the library catalog, leaving the physical files untouched. Books removed this way are hidden permanently and will not reappear during subsequent library scans.
  • Bulk deleting books is powerful — double-check your selection before confirming.
  • Deleting the last file: If you delete the only readable file from a digital book record, Fable removes the empty catalog card. To keep a catalog entry without a file, create a Physical Book entry instead.

7. BookDrop — Importing New Books

Topbar BookDrop

BookDrop is a watch folder — a special folder where you drop new book files, and Fable will detect and import them.

How It Works

  1. Place files in the BookDrop folder (located inside your main Fable installation directory on the host server, typically mapped to ./bookdrop in your Docker configuration)
  2. Fable detects the new files automatically (or you can click “Rescan”)
  3. Go to the BookDrop page in Fable to see pending files
  4. Review and edit — Adjust metadata, assign to a library, set the destination path
  5. Finalize — Click to import the files into your library

What You Can Do

ActionDescription
RescanManually trigger a scan of the BookDrop folder
Preview filesSee file details before importing
Edit metadataChange title, author, cover, etc. before import
Bulk editUpdate metadata for multiple files at once
Pattern extractionAutomatically parse filenames to extract title, author, series, etc.
Choose destinationPick which library and folder path to import into
Discard filesSkip files you don’t want to import
Finalize importMove files from BookDrop into your library
Directory tagging progressIf the destination library uses directory-based tags, a separate background task runs after the files are moved to assign tags based on the folders they are placed in

What You Can’t Do

  • Import files directly from a URL or the internet — you must first download them to the BookDrop folder
  • Import unsupported file formats (stick to PDF, EPUB, MOBI, AZW3, FB2, CBZ, CBR, CB7, and audio formats)
Be Careful:
  • Files are moved, not copied, during import. After finalization, the original file in BookDrop is removed.
  • Pattern extraction is only as good as your filename. If filenames are messy, you may need to edit metadata manually.
  • Don’t put files into BookDrop while a scan is actively running. Wait for the scan to complete first, then add files and rescan.
  • Import completion vs. directory tagging: Because directory tagging runs as a separate background task, wait for the **Directory Tags** task to finish before assuming all folder-based tags are completely applied.

9. Magic Shelves — Smart Filtered Collections

Magic Shelves are automatic collections that populate themselves based on rules you define. Unlike regular shelves where you manually add and remove books, Magic Shelves use a powerful rule engine to decide membership automatically. Change a book's metadata, and it may appear or disappear from your Magic Shelves without any manual work.

What Is Embedding?

Think of embedding as Fable reading a book and creating a searchable "index card" for it. Just like a library card catalog lets you find books by topic without reading every page, Fable's AI reads your book's text, converts it into a mathematical representation (called a vector), and stores it in a database. When you ask a question like "find books with dragons," Fable compares your question against all those index cards to find the best matches — even if the word "dragon" never appears in the title or author fields. This is what makes AI Search so powerful: it understands meaning, not just keywords.

AIS Badge Color States — The AIS badge on book cards changes appearance to tell you the embedding status at a glance:

  • AIS Cyan on black — Book is fully embedded and ready for AI Search. Click the badge to ask questions about this book.
  • AIS Grey on grey — Book is marked for embedding but hasn't been processed yet. The AI service will pick it up on the next scan. Not clickable.
  • AIS Orange on black — Book was embedded with a different AI model than the one currently configured. The embeddings are stale and the book needs to be re-embedded. Click to see which model was used.

Save to Notepad: When you find a useful AI response, you can click the "Add to Notepad" button to save that snippet into your Fable Notepad for future reference.

Sparkle Button Status Indicators — The sparkle in the search bars uses color and animation to reflect the AI Search service state:

  • Solid cyan — Service is ready. Click to open AI Search.
  • Flashing orange (800ms grey↔orange) — Service is warming up / downloading the embedding model. Wait for initialization.
  • Flashing red (800ms grey↔red) — Last search returned an error or no results. Click the sparkle to dismiss and retry.
  • Solid red — AI Search service is unreachable or encountered a fatal error. Check container logs.
  • Flashing cyan (800ms grey↔cyan) — A search is currently in progress. Results will appear in the dialog when ready.
Zero Configuration Needed:

Fable comes with everything you need built-in! The AI search engine runs automatically inside its own secure container. You don't need to install any external software or configure network settings to get started. Just pick a preset in your .env file and enjoy.

How to Set Up an Independent, Sandboxed Profile

To set up an independent profile for another person that is sandboxed (so they only see their own books and manage their own progress):

  1. Prepare Isolated Folders: Go to the host machine's filesystem where your Fable docker-compose.yml file is located. Navigate into the books directory (which is bind-mounted to /books inside the container). Inside this folder on your host machine, create a new subfolder for each user (e.g., books/user1 and books/user2). Tip: You do not need to edit your docker-compose.yml or restart Docker! Because the parent books directory is already mounted, any subdirectories you create there are automatically and instantly visible inside the container at /books/user1, /books/user2, etc.
  2. Create the New Library: Log in as an Admin. Go to Settings → Library Management and create a new library (e.g., "User 2 Books"). Point its paths to the isolated directory (e.g., /books/user2).
  3. Create the User Account: Go to Settings → User Management and click Create User. Fill in their username, display name, and password.
  4. Restrict Library Access: In the library mapping settings for the new user, select only their library ("User 2 Books") and uncheck all others. Do not check the "Admin" role.
  5. Restrict Permissions: Keep the "Library Management" permission **disabled** for the new user. If they should not be allowed to delete files from disk, keep the "Book Deletion" permission **disabled** as well.
Multi-Tenancy Caveats & Security Risks:
  • The “Book Deletion” permission allows permanent file deletion from disk. Only grant this to trusted users. You can disable deletion globally under Settings → File Management.
  • Library Management permission allows creating and deleting libraries. If regular users have this, they can add folders mapping to other users' directories, breaking the sandbox. Keep this disabled.
  • Admins bypass all sandboxes. Admin accounts automatically see and have full access to all libraries.
  • Shared Container & Database. All profiles run in the same Docker container and write to the same MariaDB instance. There is no OS-level virtualization or network isolation between users.
  • Shared Resources. Heavy backend tasks like directory rescans, metadata updates, and AI searches use shared server resources and may affect performance for other active sessions.

Search Tuning Parameters

Settings AI Search Settings Search Tuning section

These sliders control how the AI Search retrieves and presents results. Each has a range slider with −/+ stepper buttons and a direct numeric input:

  • Top K (1–50, default 5): How many context chunks to retrieve from the vector database. More chunks give the LLM richer context but increase processing time.
  • Display Top K (1–50, default 1): How many raw results to show in the UI. Set this lower than Top K to give the LLM more context while showing only the best match to the user.
  • Similarity Threshold (0.10–0.90, default 0.30): Minimum relevance score for a chunk to be included. Lower values return more results (some may be less relevant); higher values are stricter.
  • Max Tokens (128–4096, default 768): Maximum length of the LLM’s generated summary. Higher values produce longer answers but take more time and memory.
  • Temperature (0.0–1.0, default 0.1): Controls randomness in the LLM output. 0.0 gives deterministic, focused answers. Higher values (0.5+) produce more creative and varied responses.

RAG Techniques

Settings AI Search Settings RAG Techniques section

Retrieval-Augmented Generation (RAG) techniques enhance answer quality by adding processing steps between retrieval and response generation. Each technique has an independent toggle switch. Features that add LLM calls are automatically disabled when using a local LLM provider to avoid excessive latency on CPU-only hardware. They activate automatically when using an external (cloud) LLM.

  • HyDE (Hypothetical Document Embeddings): Generates a synthetic ideal answer to your query, then uses that to find similar content. Especially effective for abstract or conceptual queries. Adds 1 LLM call.
  • Multi-Query Retrieval: Expands your single query into multiple variant queries and fuses the results for broader coverage. Adds 1 LLM call + N retrievals.
  • Query Decomposition: Breaks complex questions into simpler sub-questions, answers each one, then synthesizes a complete response. Adds 1 LLM call + N retrievals.
  • Self-Reflection: After generating an initial answer, the LLM critiques its own response and regenerates if issues are found. Adds 1–2 LLM calls.
  • Contextual Compression: Filters retrieved chunks to only the most relevant sentences before they reach the LLM, keeping responses focused. No LLM calls — works with any provider.

OCR Settings

Settings AI Search Settings OCR section

Optical Character Recognition (OCR) extracts text from scanned or image-only PDF pages during book embedding:

  • OCR Language — Tesseract language code (default eng). Use three-letter codes like fra for French, deu for German, or chi_sim for Simplified Chinese.

Advanced Embedding & Retrieval Tuning

Settings AI Search Settings Advanced Embedding & Retrieval Tuning (click to expand)

This collapsible section (orange header, collapsed by default) contains low-level tuning parameters for the embedding and retrieval pipeline. It includes an Auto-Fill Recommended Presets button that loads optimal settings for your currently selected embedding model.

Be Careful: Modifying Chunk Size, Chunk Overlap, Semantic Chunking, or Matryoshka Dimensions changes how embeddings are structured. Saving changes to these settings will automatically delete all existing book embeddings and mark all books to be re-embedded. A confirmation dialog warns you before this happens. Search-only parameters (Hybrid Search or Reranking) do not invalidate existing embeddings.
  • Chunk Size (500–8000, default 1500): Maximum characters per text chunk during embedding. Larger chunks preserve more context but reduce search precision. Models with wide context windows (like Nomic at 8k) benefit from larger values.
  • Chunk Overlap (0–1000, default 100): How many characters overlap between consecutive chunks. Prevents key sentences from being cut at chunk boundaries.
  • Semantic Chunking: Toggle + threshold slider (0.10–0.50). When enabled, Fable splits books at natural text boundaries (paragraphs, sections) rather than at fixed character counts. The threshold controls how aggressively it detects boundaries — lower values create more chunks.
  • Matryoshka Dimensions: Dropdown (Disabled / 768 / 512 / 256 / 128). Supported by advanced models like Nomic, MRL allows slicing high-dimensional vectors down to fewer dimensions with almost no impact on retrieval accuracy. Slicing vectors and re-normalizing them speeds up cosine similarity comparisons on CPU by up to 3×, saving significant memory.
  • Hybrid Keyword Search (BM25 + Vector): Toggle + RRF K slider (10–200, default 60). Combines semantic vector similarity with traditional BM25 exact keyword matching using Reciprocal Rank Fusion. Highly effective at finding specific names, numbers, or technical codes that vector models might overlook.
  • Cross-Encoder Reranking: Toggle + model selector dropdown. Runs a lightweight cross-encoder model (such as BAAI/bge-reranker-base) in a background thread. While standard bi-encoders retrieve candidate chunks quickly, a cross-encoder evaluates the exact match relation between the query and text for the top candidates. This brings GPU-grade search precision to CPU hardware in milliseconds because it only reranks a handful of candidates instead of the whole database.

27. Tips and Best Practices

For New Users

  1. Start small. Set up one library, add a few books, and explore before importing your entire collection.
  2. Use BookDrop for importing rather than manually placing files.
  3. Fetch metadata early. After importing, fetch metadata to fill in titles, authors, covers, and descriptions.
  4. Create shelves to organize your favorites.
  5. Set your reading status so you can track what you’ve read.

For Security

  1. Use strong passwords for all accounts, especially the admin account.
  2. Never expose Fable directly to the internet without a reverse proxy and authentication.
  3. Keep your OPDS token private.
  4. Review user permissions carefully — only grant deletion rights to trusted users.
  5. Back up regularly — both the database and your book files.

For Performance

  1. Use CBZ over CBR when possible — ZIP extraction is faster than RAR.
  2. Keep image sizes reasonable — extremely high-resolution scans use more memory.
  3. Schedule background tasks during off-hours.
  4. Don’t scan libraries too frequently — once-daily scans are usually sufficient.

For Organization

  1. Be consistent with author names to avoid duplicates.
  2. Use genres and categories — they make filtering and Magic Shelves more useful.
  3. Rate your books — ratings enable great Magic Shelf filters.
  4. Use the Notebook to review all your annotations in one place.

Story Arcs let you create guided reading paths through your collection. Instead of reading books in publication order or series order alone, you can arrange comics, graphic novels, and books into a custom chapter-by-chapter sequence that follows a specific storyline or crossover event.

What Are Story Arcs?

A Story Arc is a curated reading order made up of chapters (rows) containing books (cards). Each chapter can represent a phase of the story, a collected edition, or a thematic grouping. Books within a chapter flow left-to-right, and chapters flow top-to-bottom with visual down-arrow connectors showing the reading path.

Story Arcs are ideal for:

  • Comic book crossover events — Arrange issues from multiple series into the correct reading order
  • Shared universe reading orders — Follow a character or team across different titles

  • Trade paperback contents — Document exactly which issues are collected in each volume
