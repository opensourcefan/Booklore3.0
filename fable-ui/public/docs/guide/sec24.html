24. Application Settings

Sidebar bottom Settings

Access settings via the gear at the bottom of the sidebar.

The main Settings page includes a compact left-arrow control in the top-right corner that returns you to the route you opened Settings from.

Settings has exactly 15 parent tabs. Tabs are permission-gated, so a normal reader sees fewer than an admin. Reader, View, Email, OPDS, and Devices are always present as parent tabs, although individual integrations can still show an access-restricted card.

Orient Yourself Inside the Larger Tabs

Reader: Mode, Reader Defaults, and Fonts

  • Application Mode controls the reading-oriented application mode offered at the top of Reader settings.
  • eBook Reader, PDF Reader, and CBX Reader contain format-specific defaults rather than one shared font-size/zoom control.
  • Custom Fonts appears only for Admin or a user with Manage Fonts permission; use it to add/manage reader fonts before selecting them in supported reader controls.

View: Browser, Filter, Sidebar, and Metadata Center Preferences

  • Library Display & Sorting sets default grid/table view, multi-field sort order, visible sort fields, auto-save metadata, the random-cover loading screen, and per-library/shelf/Magic Shelf overrides.
  • Filter Preferences selects the filter mode and lets you add, remove, and drag visible filters into order.
  • Sidebar Sorting independently sorts Libraries, Shelves, and Magic Shelves.
  • Metadata Center chooses page versus dialog display and whether Series View Mode is enabled.
  • Further children cover cover preview, resize handles, tablet/kiosk gestures, phone/tablet header position, layout mode and breakpoints, and the configurable toolbar.

Metadata 1 and Metadata 2

  • Metadata 1 starts with metadata persistence/write-back and automatic BookDrop download, then ISBN Discovery.
  • Metadata Providers holds provider enablement and provider-specific credentials/options. Provider Field Selection chooses which provider-specific fields Fable retains.
  • Public Reviews controls review downloading and sources. Metadata Match Weights controls how fields contribute to candidate matching; change weights only after testing representative books.
  • Metadata 2 applies advanced fetch options globally or as per-library overrides and exposes sidecar import/export only where the current storage mode supports it.

Devices and Hardcover

  • KOReader needs saved credentials before its sync toggles can be enabled.
  • Hardcover accepts a personal API key and sends KOReader reading progress to Hardcover; it is not a book-transfer service.
  • Kobo provides a per-user sync token and progress/shelf controls; admins additionally see conversion policy. Follow the first-use procedure in Section 20.

AI Children

  • AI Search Engine contains enable/status, LLM profiles and provider/model/API fields, result tuning, RAG techniques, OCR, embedding configuration/statistics, advanced chunking/BM25/reranking, auto-embed libraries, and manual scan controls.
  • AI Panel Detection is lower on the same AI parent page and contains enable/model ID, status/reload, directory scan/progress, stored-data statistics, and cleanup. See Section 18.

Good to Know: For CBR comics, embedded metadata writes are fastest when the Fable container has access to a compatible Linux rar binary. Without it, Fable may convert the archive to .cbz during a save-to-original-file operation.

Metadata & ISBN Discovery

ISBN Discovery Settings

Settings Metadata 1 ISBN Discovery

ISBN Discovery scans a book’s copyright/front matter and, when needed, its last pages or back cover for a checksum-valid ISBN. A verified ISBN is then used as the ground truth for fetching metadata.

  • Enable ISBN discovery — Master switch for automatic and manually launched ISBN discovery.
  • BookDrop imports — Runs discovery when a new BookDrop file is imported.
  • Library scans — Runs discovery during scans; it is off by default because large libraries make this processing intensive.
  • Use OCR for image-only pages — Lets scanned PDFs and cover images be read through the AI Search sidecar. If that sidecar is unavailable, OCR soft-fails while text-extractable files continue normally.
  • Require review before applying — Sends verified results to Review instead of applying them automatically. Ambiguous or failed discoveries still require review.
  • Write ISBN-fetched metadata to original files — Off by default and also requires write-back for that file format under Metadata Persistence.
  • Max pages to scan (front and back) — Sets how many first pages are searched, followed by the same number of last pages (including the back cover) when no ISBN is found up front.

When starting ISBN Discovery from selected book actions, the confirmation dialog also lets you choose which currently enabled metadata providers to query. The task indicator shows ISBN Fetch first, then Metadata Fetch, while books needing a decision appear in Staging → Review. Books left in the Staged inbox retain a compact exception badge on desktop and tablet: amber means the scan completed without a valid ISBN, while red means OCR or another technical problem prevented the check from completing. The badge tooltip records the reason and time; a later successful ISBN run clears the old badge.

AI Search & Embedding Tuning

Settings AI AI Search Engine

Fable’s AI Search is powered by two separate AI engines: an Embedding Engine that converts book text into searchable vectors, and an LLM (Large Language Model) Engine that generates natural-language answers to your queries. Both can run locally (via the bundled Ollama service inside the fable-ai-search Docker container) or connect to external cloud providers like OpenAI. The AI Search Engine area is organized into sections that control different parts of the AI pipeline.

AI Search Status Panel

Settings AI AI Search Engine top of area

The status panel shows the current state of the AI Search service at a glance:

  • Service State — Displays READY, STARTING, UNREACHABLE, or ERROR with a color-coded status box (green/amber/red).
  • Refresh — Manually re-check the service status.
  • Startup Activity Log — Expandable panel showing a timeline of status checks, model path, whether the model file exists on disk, and any errors. Useful for diagnosing why the service isn’t ready.
  • Reload — Triggers a model reload on the AI Search service. Use this after changing the embedding model to force the service to pick up the new model without restarting the container.
  • Docker Hint — If the service is unreachable and the endpoint looks like a Docker service name, a hint reminds you to ensure the fable-ai-search container is running.

LLM Configuration

Settings AI AI Search Engine LLM Configuration

The LLM (Large Language Model) is what generates the natural-language answers when you ask AI Search a question. This section controls which model to use and how to connect to it:

  • Active LLM Profile — A dropdown listing all your saved profiles. Select one to instantly load its provider, model, API key, and tuning parameters. The currently active profile is highlighted. If no profile matches your current settings, the dropdown shows “Custom Settings (No Profile).”
  • LLM Engine (Local / External) — Choose between:
    • Local Ollama — Uses the bundled Ollama instance inside the fable-ai-search container. No API key needed.
    • OpenAI Endpoint — Connects to OpenAI’s API. Requires an API key and the base URL (https://api.openai.com/v1).
    • Custom URL — Connects to any OpenAI-compatible API (e.g., Groq, Together, local LLM servers). Requires the full base URL.
    • External Ollama — Connects to an Ollama instance running on another machine. Use http://host.docker.internal:11434 for a host-machine Ollama.
  • LLM Model Name — For local Ollama, choose from preset models (smollm2:360m, qwen2.5:1.5b, qwen2.5:3b, llama3.2:3b) or type any model name from the Ollama registry. For external providers, type the model ID (e.g., gpt-4o-mini).
  • LLM API Key — Required for external providers. Stored securely.
  • External LLM URL — The base URL for the external API endpoint. Required for all non-local providers.
  • Test Connection — Sends a test request to verify the LLM endpoint is reachable and the API key works.
  • Downloaded Models — Right-side panel showing all LLM models currently downloaded in the local Ollama instance, with file sizes. Click a model name to prefill it into the LLM settings.
  • Apply LLM Settings — Saves the LLM configuration. The button turns green when changes are detected.

Embedding Configuration

Settings AI AI Search Engine Embedding Configuration (click to expand)

The Embedding Engine converts book text into mathematical vectors that power semantic search. This section is collapsed by default with an orange warning header because changing the embedding model requires re-embedding all books:

  • Embedding Engine (Local / External) — Same provider options as the LLM: Local Ollama, OpenAI, Custom URL, or External Ollama.
  • Embedding Model Name — For local, choose from presets (all-MiniLM-L6-v2, bge-base-en-v1.5, nomic-embed-text-v1.5) or type any HuggingFace model ID. For external, enter the provider’s embedding model name (e.g., text-embedding-3-small).
  • Embedding API Key — Required for external providers.
  • External Embedding URL — Base URL for the external embedding API.
  • Test Connection — Verifies the embedding endpoint is reachable.
  • Downloaded Models — Right-side panel listing all embedding models downloaded locally, with sizes and delete buttons.
  • Embedding Statistics — Shows how many books are embedded with each model. If a model doesn’t match the currently selected one, it shows a (Mismatch) warning in orange — those embeddings are stale and books need re-embedding.
  • Apply Embedding Settings — If the provider or model changed, a confirmation dialog warns that all existing embeddings will be invalidated and books must be re-embedded.

Saved LLM Profiles

Settings AI AI Search Engine Saved LLM Profiles

Profiles let you save and switch between complete AI configurations instantly. Each profile stores: LLM provider, model, API key, external URL, Max Tokens, Temperature, and all RAG technique toggles.

  • Save Profile — Opens a dialog where you name the profile. The name defaults to the current model name. The description is auto-generated from the provider type, temperature, and max tokens.
  • Activate Profile — Click any saved profile in the dropdown to instantly load all its settings. The active profile is highlighted.
  • Delete Profile — Removes the selected profile. Does not affect current settings.
  • Profile-Aware Save — When you save settings that match an existing profile, the profile selector updates to show that profile as active. When you change settings away from a profile, it switches to “Custom Settings.”

Search Tuning Parameters

Settings AI AI Search Engine Search Tuning

These sliders control how the AI Search retrieves and presents results. Each has a range slider with −/+ stepper buttons and a direct numeric input:

  • Top K (1–50, default 5): How many context chunks to retrieve from the vector database. More chunks give the LLM richer context but increase processing time.
  • Display Top K (1–50, default 1): How many raw results to show in the UI. Set this lower than Top K to give the LLM more context while showing only the best match to the user.
  • Similarity Threshold (0.10–0.90, default 0.30): Minimum relevance score for a chunk to be included. Lower values return more results (some may be less relevant); higher values are stricter.
  • Max Tokens (128–4096, default 768): Maximum length of the LLM’s generated summary. Higher values produce longer answers but take more time and memory.
  • Temperature (0.0–1.0, default 0.1): Controls randomness in the LLM output. 0.0 gives deterministic, focused answers. Higher values (0.5+) produce more creative and varied responses.

RAG Techniques

Settings AI AI Search Engine RAG Techniques

Retrieval-Augmented Generation (RAG) techniques enhance answer quality by adding processing steps between retrieval and response generation. Each technique has an independent toggle switch. Features that add LLM calls are automatically disabled when using a local LLM provider to avoid excessive latency on CPU-only hardware. They activate automatically when using an external (cloud) LLM.

  • HyDE (Hypothetical Document Embeddings): Generates a synthetic ideal answer to your query, then uses that to find similar content. Especially effective for abstract or conceptual queries. Adds 1 LLM call.
  • Multi-Query Retrieval: Expands your single query into multiple variant queries and fuses the results for broader coverage. Adds 1 LLM call + N retrievals.
  • Query Decomposition: Breaks complex questions into simpler sub-questions, answers each one, then synthesizes a complete response. Adds 1 LLM call + N retrievals.
  • Self-Reflection: After generating an initial answer, the LLM critiques its own response and regenerates if issues are found. Adds 1–2 LLM calls.
  • Contextual Compression: Filters retrieved chunks to only the most relevant sentences before they reach the LLM, keeping responses focused. No LLM calls — works with any provider.

OCR Settings

Settings AI AI Search Engine Automatic OCR Fallback

Optical Character Recognition (OCR) extracts text from scanned or image-only PDF pages during book embedding:

  • Enable OCR — Master toggle. When on, Fable runs OCR on pages that have no extractable text layer.
  • OCR Fallback Only — When enabled, OCR only runs on pages where no text could be extracted normally. This avoids unnecessary OCR processing on pages that already have text.
  • OCR Language — Tesseract language code (default eng). Use three-letter codes like fra for French, deu for German, or chi_sim for Simplified Chinese.

Auto-Embed Libraries

Settings AI AI Search Engine Auto-Embed Libraries

A multi-select dropdown listing all your libraries. Books imported into selected libraries are automatically queued for embedding in the background. If no libraries are selected, you must manually trigger embedding via the scan section below.

AI Search Scan

Settings AI AI Search Engine Manual Scan

This section lets you manually trigger embedding for books that don’t yet have AI Search data:

  • Directory Picker — Select which library directories to scan for unembedded books.
  • Scan Now — Starts scanning the selected directories. Books found without embeddings are queued for processing.
  • Progress Display — Shows a live progress box with status text (e.g., “Processing book 12 of 45”), error details if any, and a Stop button to cancel the scan.
  • Stop — Cancels the running scan. Already-processed books keep their embeddings.

Advanced Embedding & Retrieval Tuning

Settings AI AI Search Engine Advanced Embedding & Retrieval Tuning (click to expand)

This collapsible section (orange header, collapsed by default) contains low-level tuning parameters for the embedding and retrieval pipeline. It includes an Auto-Fill Recommended Presets button that loads optimal settings for your currently selected embedding model.

Be Careful: Modifying Chunk Size, Chunk Overlap, Semantic Chunking, or Matryoshka Dimensions changes how embeddings are structured. Saving changes to these settings will automatically delete all existing book embeddings and mark all books to be re-embedded. A confirmation dialog warns you before this happens. Search-only parameters (Hybrid Search or Reranking) do not invalidate existing embeddings.
  • Chunk Size (500–8000, default 1500): Maximum characters per text chunk during embedding. Larger chunks preserve more context but reduce search precision. Models with wide context windows (like Nomic at 8k) benefit from larger values.
  • Chunk Overlap (0–1000, default 100): How many characters overlap between consecutive chunks. Prevents key sentences from being cut at chunk boundaries.
  • Semantic Chunking: Toggle + threshold slider (0.10–0.50). When enabled, Fable splits books at natural text boundaries (paragraphs, sections) rather than at fixed character counts. The threshold controls how aggressively it detects boundaries — lower values create more chunks.
  • Matryoshka Dimensions: Dropdown (Disabled / 768 / 512 / 256 / 128). Supported by advanced models like Nomic, MRL allows slicing high-dimensional vectors down to fewer dimensions with almost no impact on retrieval accuracy. Slicing vectors and re-normalizing them speeds up cosine similarity comparisons on CPU by up to 3×, saving significant memory.
  • Hybrid Keyword Search (BM25 + Vector): Toggle + RRF K slider (10–200, default 60). Combines semantic vector similarity with traditional BM25 exact keyword matching using Reciprocal Rank Fusion. Highly effective at finding specific names, numbers, or technical codes that vector models might overlook.
  • Cross-Encoder Reranking: Toggle + model selector dropdown. Runs a lightweight cross-encoder model (such as BAAI/bge-reranker-base) in a background thread. While standard bi-encoders retrieve candidate chunks quickly, a cross-encoder evaluates the exact match relation between the query and text for the top candidates. This brings GPU-grade search precision to CPU hardware in milliseconds because it only reranks a handful of candidates instead of the whole database.

Be Careful:
  • Changing authentication settings can lock you out. Test OIDC configuration before disabling local login.
  • Settings export/import includes sensitive data (email credentials, API keys). Store exported files securely.
  • Allow File Deletion is a hard safety gate. When it is off, Fable hides the Delete from Disk action, removes catalog associations only, and should not delete physical files from disk.
Good to Know:
  • The File Management toggle also protects additional attached files. When Allow File Deletion is disabled, deleting an attached file removes it from Fable without overriding the global disk-deletion block.
  • Remove from Library is a durable hide action. When you remove a book without deleting its file, Fable keeps the file on disk but suppresses automatic re-import during later scans and watcher events.
  • Automatic sidecars and manual sidecar backups are separate. You can keep automatic sidecar writing turned off and still run Back Up Sidecars per Library from Metadata Persistence when you want an on-demand metadata backup.
  • The backup action is available in both LOCAL and NETWORK disk modes. Network mode blocks automatic rewrite and file reorganization, but the manual sidecar backup action remains available as an explicit exception.
  • Running the backup again refreshes existing backup sidecars. Fable rewrites the selected library’s sidecar files with the current database metadata instead of requiring you to delete old backups first.
  • Manual sidecar backups show a light grey topbar working pill while they run. The message is intentionally simple because the backup call is usually brief, but it gives you immediate confirmation that the action started.
