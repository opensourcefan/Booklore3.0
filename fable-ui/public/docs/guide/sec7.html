7. BookDrop — Importing New Books

Topbar BookDrop

BookDrop is a watched, pre-import inbox. Files stay outside normal library browsing while you inspect metadata, choose a destination library and subpath, and finalize them. Finalization imports the book into its library; it does not bypass the Staging lifecycle.

Good to Know: The global BookDrop is the shared/admin inbox inside the container (default /bookdrop, commonly mounted from a host folder such as ./bookdrop). Non-admin accounts use private inboxes under /books/_users/{id}/bookdrop/.

Put Files into BookDrop

MethodDestination
Browser uploadOpen topbar Upload, choose BookDrop, select files, and upload. An admin upload goes to the global/shared inbox; a non-admin upload goes to that user’s personal inbox.
Host dropCopy files into the host directory mounted as the global BookDrop. This feeds the admin/shared queue.
Personal dropPlace files in the user’s /books/_users/{id}/bookdrop/ inbox, or use browser upload while signed in as that user. A .ignore marker keeps this inbox out of normal personal-library scans.

Use direct topbar Upload → Library instead when the library and subpath are already known and you do not need BookDrop’s pre-import review. The route comparison is in Section 6.

Review and Finalize

  1. Wait for detection or click Rescan, then open topbar BookDrop.
  2. Select pending files. Selection can cover the current page or all pages.
  3. Prepare metadata. Review fetched values, import selected metadata, bulk-edit fields, or extract metadata from filename patterns.
  4. Choose a destination. Assign a permitted library and subpath to every selected file; defaults can be applied to the selection.
  5. Finalize. Fable resolves the library naming pattern, moves each successful file into its destination, creates the library book record, applies the prepared metadata, and removes successful items from BookDrop. Failed items are reported in the import summary.
  6. Hand off to Staging. Open HOME → Staging, resolve any remaining metadata work, and release the new books when ready. See Section 6: Staging lifecycle.
Be Careful: Finalization applies the destination library’s naming pattern and moves the source file; it does not overwrite an existing destination silently. Resolve naming collisions before retrying. Successful items leave BookDrop because their source files were moved, while failed items remain for review and cleanup.

Use BookDrop Actions

ActionDescription
RescanManually trigger a scan of the BookDrop folder
Preview filesSee file details before importing
Edit metadataChange title, author, cover, etc. before import
Bulk editUpdate metadata for multiple files at once
Pattern extractionAutomatically parse filenames to extract title, author, series, etc.
Choose destinationPick which library and folder path to import into
Delete pending filesPermanently delete selected files from BookDrop after confirmation
Finalize importMove successful files into the chosen library and create staged book records
Directory tagging progressIf the destination library uses directory-based tags, a separate background task runs after the files are moved to assign tags based on the folders they are placed in

Check Permissions and Format Limits

Admins work with the global/shared queue. Non-admin users work only with pending files owned by their account and can finalize only to libraries and subpaths they are permitted to use. Available actions and destination choices follow those permissions.

  • Import files directly from a URL or the internet — you must first download them to the BookDrop folder
  • Import unsupported or library-disallowed formats. Supported choices include PDF, EPUB, MOBI, AZW3, FB2, CBZ, CBR, CB7, MP3, M4A, M4B, and OPUS, subject to the destination library’s allowed formats.
Be Careful:
  • Pattern extraction is only as good as your filename. If filenames are messy, you may need to edit metadata manually.
  • Import completion vs. directory tagging: Because directory tagging runs as a separate background task, wait for the Directory Tags task to finish before assuming all folder-based tags are completely applied.
