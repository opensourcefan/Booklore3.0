CPU Inference Optimization Tips
  • For nomic-embed-text-v1.5: Set Chunk Size to 3000-8000 (supports 8192 context). Enable Matryoshka Truncation to 256 or 512 dimensions for up to 3x CPU speedup with near-zero accuracy loss.
  • For all-MiniLM-L6-v2: Set Chunk Size to 1000-1500. Disable Matryoshka Truncation. Enable Cross-Encoder Reranking to yield high accuracy at blazing CPU speeds.

{{ advancedChunkSize }} chars

Sets the max length of book text pieces to index. Larger chunks hold more context but dilute detail; smaller chunks are precise. Modifying this clears the index.

{{ advancedChunkOverlap }} chars

Ensures surrounding context is preserved at the boundaries of adjacent text chunks, preventing sentences from being sliced in half. Modifying this clears the index.

Truncates output vector size for supported models. Slicing vectors to 256 or 128 speeds up similarity computations on CPU. Modifying this clears the index.

{{ aiSearchSettings.topK }}

How many context chunks to retrieve (1–50). More chunks give the LLM more context but takes longer to process.

{{ aiSearchSettings.similarityThreshold }}

How strict the search match should be (0.1–0.9). Lower values return more potential matches.

{{ aiSearchSettings.maxTokens }}

The maximum number of tokens (128–4096) the LLM can generate in its summary.

{{ aiSearchSettings.temperature }}

Controls creativity vs determinism (0.0–1.0). Lower values (e.g. 0.1) are better for factual summaries.
